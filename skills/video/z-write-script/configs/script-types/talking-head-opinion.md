# Purpose
This script type is for a longform talking-head opinion piece that argues a thesis.

# Hard Rules

## Claims Need Dated, Verifiable Facts
- Every claim about a company, tool, or feature must trace to something found in research.
    - A launch or changelog entry, a docs page, a pricing page, an announcement, a public statement.
- Include when the fact happened (month and year) in the script if it supports the point.
- If a claim can't be backed, cut it or phrase it explicitly as a personal opinion.

## Name Real Products, Never Generic
- No "some tools do X" or "a lot of apps are adding Y".
- Always name the actual product and say what it actually does.

# Guidelines

## Thesis First, Sections Are Evidence
- State the thesis up front in the Intro.
- Each section is one piece of evidence that supports the thesis.
- The conclusion should feel inevitable given the evidence presented before it.

## Personal Experience Is Evidence
- Hands-on experience with the tools counts as first-class evidence alongside research.
- When there is a personal story, lead with it, then back it with research.

## Dates and Timelines Matter
- When something launched, pivoted, or shut down is part of the argument.
- Say when things happened, and use the ordering of events to show the trend.

## Show Where the Thesis Doesn't Hold
- Include the exceptions and the cases where the thesis breaks down.
- It's ok to concede a point, conceding builds trust in the rest of the argument.

## Online Content Cues
- Add cue's to show products, webpages, video clips, etc. when they help explain a point, add weight to a point, or help illustrate what is being said.
- Always include a link to the online content with instructions of what to show.
- Do not overdo this, simple points need no support from other content.
